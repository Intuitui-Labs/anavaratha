# Anavaratha Validation and Scale-Up Plan

## 1. Validation philosophy

Anavaratha should earn trust by making uncertainty visible. The pilot is successful when an independent reviewer can trace a summary number back to a measurement event, source, method, date, boundary, and assumption. A polished interface is secondary to reproducibility.

## 2. Quality-control gates

| Gate | Test | Minimum evidence |
|---|---|---|
| Definition gate | All categories, units, boundaries, and status labels are documented | Approved glossary and data dictionary |
| Access gate | Local authority and facility permissions are confirmed | Named focal points and written permissions |
| Field gate | Observers can repeat the protocol consistently | Training exercise and inter-observer check |
| Data gate | Each record has source, date, unit, boundary, and confidence | Completeness report |
| Reconciliation gate | Major inflows and outflows are compared without hiding unknowns | Mass-balance and uncertainty register |
| Stakeholder gate | Operators and affected communities can challenge interpretations | Validation workshop record |
| Publication gate | Sensitive information is protected and public maps are appropriately generalized | Privacy and safety review |

## 3. Field validation

Use duplicate observations for a subset of routes, samples, and hotspots. Compare independently recorded masses, categories, destinations, and coordinates. When discrepancies occur, record the cause rather than merely averaging the values. Causes may include mixed loads, changing schedules, rain, unrecorded informal diversion, scale differences, or category ambiguity.

Repeat a smaller set of measurements after the first data-cleaning cycle. The second visit should test whether the observed flow is persistent and whether the protocol has been understood consistently. For accumulation hotspots, persistence should be based on repeat visits rather than a single photograph.

## 4. Cross-validation with administrative records

Compare field totals with local-authority route logs, facility registers, weighbridge data, contractor invoices, fuel or trip records, recycling receipts, and operator interviews. Administrative records should not automatically override field observations; they should be compared by time period and boundary. Differences are findings that may reveal undocumented flows or definition mismatches.

## 5. Model validation

Do not begin with a predictive model. First validate the descriptive baseline. Once a reliable time series exists, test simple transparent models against a held-out period. Compare any forecast with a naive seasonal baseline and report error ranges. A model must never be used to justify infrastructure or policy decisions if its training data are sparse, unrepresentative, or not traceable.

## 6. Intervention evaluation

For each intervention, define a baseline, a responsible owner, an implementation period, and a measurable outcome. For example, a source-separation intervention could be evaluated through the proportion of sampled generators separating correctly, contamination of separated fractions, recovered mass, residual mass, and service reliability. A hotspot intervention could be evaluated through repeat observations, cleanup persistence, drain or waterway condition, and displacement to nearby locations.

| Intervention type | Example outcome measures |
|---|---|
| Source separation | Participation, contamination, recovered material, residual disposal |
| Route improvement | Coverage, missed stops, collection reliability, cost per tonne |
| Organic recovery | Feedstock quantity, contamination, compost or product output, residuals |
| Plastic recovery | Material captured, quality, downstream destination, leakage avoided |
| Hotspot remediation | Persistence after intervention, repeat dumping, nearby leakage, community feedback |
| Worker-safety improvement | PPE availability, incidents, exposure observations, training coverage |

## 7. Scale-up sequence

Scale Anavaratha in layers. First, repeat the same method in a second local authority to test portability. Second, add a district-level aggregation view only after local records share compatible definitions. Third, add new material modules such as e-waste, construction waste, agricultural residues, or hazardous waste only with specialized partners. Fourth, connect the atlas to investment and policy planning, including collection optimization, recovery markets, and environmental-risk reduction.

The scale-up decision should be based on evidence rather than enthusiasm. Proceed when the pilot has a stable glossary, a documented protocol, repeatable measurements, stakeholder validation, and a clear set of decisions that the system improves.

## 8. Long-term value pathways

Anavaratha can create value through better collection planning, targeted infrastructure investment, recovery-market intelligence, hotspot prevention, environmental-risk prioritization, worker-safety improvements, community accountability, and evidence for circular-economy programs. It should avoid presenting waste as a simple commodity opportunity. The value of a pathway depends on contamination, logistics, market demand, worker conditions, residuals, and environmental controls.

## 9. Governance and data stewardship

The project should establish a data governance charter covering ownership, access levels, correction procedures, public release, attribution, retention, and deletion. The public atlas should show aggregated zones and validated system-level flows. A restricted operational layer may contain exact facility coordinates, route details, private records, personal information, and worker-sensitive data. Any publication involving informal workers or vulnerable communities should use consent-based participation and avoid identifying individuals without explicit permission.
