# Anavaratha: Documentation Index

**Version:** 0.1  
**Date:** 25 August 2026  
**Geography:** Sri Lanka

## 1. How to use this index

This index separates Anavaratha’s **canonical architecture**, **domain frameworks**, **evidence and analysis reports**, **methods and protocols**, **data registers**, and **source archives**. The project should begin with the canonical documents before reading the detailed waste or GIS outputs.

The three domains are:

1. **Freedom from Waste**;
2. **Material Afterlives**;
3. **Ecological Flourishing**.

The present evidence base is strongest for the first domain. The second domain is now defined conceptually and is ready for a separate desk-based evidence programme. The third domain is intentionally kept as a distinct axis for later development.

## 4. Domain II — Material Afterlives

The domain is currently defined by the canonical architecture as **Material Afterlives: Latent Utility, Reuse, and Post-Use Circulation**. It includes used goods, surplus, repair, exchange, sharing, resale, donation, refurbishment, remanufacture, salvage, component recovery, material banks, and eventual residuality.

The next documentation should create:

- a post-use state ontology;
- an object and asset register;
- a latent-utility ledger;
- a repair and exchange network model;
- a safety and quality protocol;
- a second-life duration and persistence measure;
- and a final-afterlife residual account.

No domain-specific dataset is yet treated as established in this project. The domain should begin with desk research and source mapping rather than immediate platform development.

## 5. Domain III — Ecological Flourishing

Ecological Flourishing is a separate axis concerning ecological capability, regeneration, soils, forests, wetlands, waterways, habitats, biodiversity, trees, restoration, and stewardship.

The next documentation should create:

- an ecological capability ontology;
- a receiving-environment and ecological-condition register;
- a restoration-event and persistence ledger;
- a catchment and habitat GIS framework;
- a material-pressure interface with the waste and afterlife domains;
- and an ethics protocol for more-than-human claims.

Ecological activity must not be treated as ecological flourishing without evidence of condition, function, trajectory, and persistence.

## 8. Status and version rules

A **canonical** file defines project architecture or terminology. A **protocol** defines how evidence is acquired or interpreted. A **report** synthesizes evidence. A **register** preserves machine-readable records. A **source archive** preserves the underlying document. A **map or chart** is a derived visualization and must not replace the underlying data.

Version numbers should increase when definitions, boundaries, methods, or interpretation change. If an earlier interpretation is corrected, the replacement file should state that it supersedes the earlier version and preserve the correction reason.
